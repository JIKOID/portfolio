광고 네트워크·퍼블리셔·MMP의 마케팅 데이터를 수집하는 파이프라인을 운영하고, 게임별 병렬 처리와 목적별 DAG 구조를 정비했습니다.

### 담당 업무
- Moloco, AppLovin, Unity Ads, Google Ads 등 광고 네트워크 API 기반 데이터 수집 파이프라인 운영
- Airflow에서 Cloud Run 작업을 실행해 게임별 Bundle ID 단위로 병렬 처리
- 네트워크사별 API 토큰 만료에 대응해 토큰 갱신·적용
- 단일 마케팅 DAG를 KPI·소재·리텐션 등 목적별 DAG로 분리·리팩터링
- AppsFlyer SSoT 데이터 수집 체계로 전환하고 기존 SKAN API 파이프라인 제거
- 신규 게임 소프트 런칭 시 마케팅 수집 파이프라인 적용

### 수집 안정성 개선 (2026.09 – 2026.11)
- Cloud Run API의 503 오류에 대응해 작업 조회·생성·수정·실행 호출에 재시도 처리 적용
- Moloco 리포트 수집 실패를 추적할 수 있도록 실패 건수 로그 보강
- 게임 운영 상태 설정으로 수집 대상에서 제외된 광고 비용 데이터의 원인을 확인하고 설정 수정·데이터 갱신

### 지표 정합성과 설계 판단
- 광고 매출 차이를 조사해 매체의 소수점 제공 범위와 실제 지급 추정액·비딩 낙찰가 기준의 차이 확인
- 기존 수집 데이터를 유지하면서 광고 매출 통합 방안을 검토하고, 매체별 지표 해석 기준 공유
- 별도 마케팅 팩트 마트를 설계했으나 기존 KPI 테이블과 데이터가 중복되고 관리 부담이 늘어나는 구조로 판단해 구축을 진행하지 않기로 결정 (2026.11)
